# Input Bar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Warp-style input bar with a native header for idle zsh panes, replacing the shell prompt.

**Architecture:** PrompTTY injects its own zsh integration through `ZDOTDIR`, hides the prompt, and learns
"prompt ready" from an OSC 7 it emits at every prompt. A pure `CommandEditing` library holds every rule
(state machine, vi engine, history, suggestions, tokenizer, completion, git status, integration
scripts); the app hosts an `NSTextView`-based bar per pane and routes focus between bar and terminal.

**Tech Stack:** Swift 6, SwiftUI + AppKit, libghostty (GhosttyKit 0.2.0), XCTest, zsh.

**Spec:** `docs/superpowers/specs/2026-10-12-input-bar-design.md`

## Global Constraints

- macOS 26, Swift 6 strict concurrency; `CommandEditing` imports Foundation only (no AppKit).
- No user settings for the bar; it is always on for zsh panes; Reduce Motion only removes the fade.
- Never read `.env` files.
- Keys while a program runs must reach libghostty exactly as before (Neovim must be unaffected).
- App shortcuts stay ⌘-only; ⌃ keys inside the bar are editor keys.
- Every task ends with `swift test` green and, for app tasks, `xcodebuild` green.

## Review Focus

1. A pane whose `.zshrc` errors or exits early: the bar must still appear (or the pane stays a usable terminal).
2. Type-ahead while a command runs must not prefix the next bar command.
3. A program that reads stdin (`cat`, `read`, `python`) must get keys: the bar must not reappear while it runs.
4. History with multi-line and non-ASCII (metafied) entries must round-trip into the bar unchanged.
5. Moving a pane (split rearrange, other tab, other window) must keep its bar text, state, and focus.

### Task 1: `CommandEditing` package and the pane state machine

**Files:** Create `Sources/CommandEditing/ShellPaneState.swift`, `Tests/CommandEditingTests/ShellPaneStateTests.swift`; modify `Package.swift` (library + test target), `project.yml` (app depends on `CommandEditing`).

**Produces:**
```swift
public enum ShellPhase: Equatable, Sendable { case starting, idle, running }
public struct ShellPaneState: Equatable, Sendable {
    public private(set) var phase: ShellPhase      // .starting
    public private(set) var shellPID: Int?
    public private(set) var lastExit: CommandExit? // code + duration
    public mutating func pwdReported(foregroundPID: Int) -> Bool   // returns true when it became idle
    public mutating func submitted()
    public mutating func commandFinished(code: Int, durationNanoseconds: UInt64)
    public mutating func foregroundChanged(to pid: Int)
}
public struct CommandExit: Equatable, Sendable { public var code: Int; public var duration: TimeInterval }
```
Tests: starts `starting`; first pwd sets `shellPID` and becomes idle; pwd while a child is foreground stays running; submitted → running; pwd with shell pid → idle; foreground change while idle → running; commandFinished records exit (code −1 kept as "unknown"); pwd while idle is a no-op returning false.

### Task 2: zsh integration scripts, installer and state file

**Produces:**

public enum ZshIntegration {

The script follows spec §1 exactly. Tests: parse every line kind, ignore junk lines, values with spaces (`path`), install writes the file and is idempotent, `isZsh` for `/bin/zsh`, `/opt/homebrew/bin/zsh`, `/bin/bash`; script contains the init/precmd/preexec hooks, `unsetopt HIST_VERIFY`, the line-init hook, OSC 7 and cursor escapes; plus `zsh -n` syntax check of the script (skipped when `/bin/zsh` is absent).

### Task 3: zsh history

**Files:** Create `Sources/CommandEditing/ZshHistory.swift`, `Sources/CommandEditing/HistoryNavigator.swift`, tests.

**Produces:**
```swift
public enum ZshHistory { public static func parse(_ data: Data) -> [String] }   // oldest → newest, unmetafied
public struct CommandHistory: Sendable {
    public init(fileEntries: [String]); public mutating func add(_ command: String)
    public var newestFirst: [String] { get }          // deduplicated, newest kept
}
public struct HistoryNavigator: Sendable {
    public init(history: [String]); public mutating func older(current: String) -> String?
    public mutating func newer() -> String?            // nil past newest → caller restores draft
    public var draft: String? { get }
}
```
Tests: extended format, plain lines, `\`-continued multi-line, metafied bytes (`0x83` + `x^0x20`) incl. UTF-8 like "é" and "→", trailing empty line, CRLF-free; dedupe keeps newest; navigator walks older/newer and restores the draft.

### Task 6: Edit buffer and vi engine

**Files:** `Sources/CommandEditing/EditBuffer.swift`, `Sources/CommandEditing/ViEngine.swift`, tests (table-driven).
**Produces:**
```swift
public struct EditBuffer: Equatable, Sendable { public var text: String; public var cursor: Int } // UTF-16 offset
public enum ViMode: Equatable, Sendable { case insert, normal }
public enum ViKey: Equatable, Sendable { case char(Character), escape }
public enum ViResult: Equatable, Sendable { case handled, unhandled, historyOlder, historyNewer, submit }
public struct ViEngine: Sendable {
    public private(set) var mode: ViMode            // .insert
    public private(set) var register: String
    public mutating func handle(_ key: ViKey, buffer: inout EditBuffer) -> ViResult
    public mutating func enterInsert()
}
```
Insert mode handles only Escape (→ normal, cursor −1 clamped to line start); everything else `.unhandled` (native editing). Normal mode covers the spec §3 list. Undo is the text view's (each normal-mode change is one undo group, done by the app). Tests per command, counts, operator+motion, `iw/aw`, register fill/paste, `j/k` → history results on first/last line, unknown keys handled (swallowed) in normal mode.

### Task 9: Shell sessions in the app (no bar UI yet)
